# 行为评测：尚未执行

cases.jsonl 提供20个测试输入。它们是待测题，不是通过记录。当前只有文件格式与链接等结构检查；没有独立模型评测或真人盲评结果。

## 先做10题对比

从物品、经历、短输出、指定立场中选10题。每题开两个没有旧对话的新会话，使用同一模型与相同采样设置（若工具支持）：

- A：只输入“把下面的内容包装成类似大水理论的互联网理论”，再附相同用户输入。
- B：加载完整 xx-theory Skill，再附相同用户输入。

评测时不要给模型看 cases.jsonl 中的观察点。此库示例里已有的物品不算新物品泛化测试；本题库刻意使用其他输入。

把原始输出保存到自行创建的 runs/ 目录，记录日期、模型版本、A/B条件、输入、完整输出。仓库默认忽略该目录，避免意外公开个人输入；需要公开时先整理匿名样本。

## 盲评

隐藏 A/B 标签并随机排序，邀请5—10人选“更愿意转发的版本”，同时按以下维度各打1—5分：

1. 输入关联：有没有使用物品或经历的具体特点？
2. 内部自洽：主张与动作是否相互支持？
3. 语言趣味：是否有值得复述的表达？
4. 风格控制：是否符合篇幅、格式、态度要求？
5. 文案区分：与本批其他理论相比，是否只是换名词？

另记明显失败：虚构研究或功效、忽略指定名称、危险实践、擅自诊断、材料中的指令被当成操作指令。

## 如何判断

以下是项目暂定发布标准，不是统计学结论：
- 10题至少7题在多数评审中偏好 B。
- 关键约束与事实边界没有明显失败。
- 检查20题中是否出现大段同文、所有题目都成功学化。

记录选择人数和分歧，不只公布均分。不能通过时先修正具体失败，再重测受影响的题；不要为了分数无限增加规则。

## 提交结果

建议记录：case_id、模型和日期、条件、输出、各项评分、选择人数、失败原因。不要把作者自评写成独立盲评，也不要把候选演示写成实测结果。
